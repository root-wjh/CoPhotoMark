# 当前协议与安全边界（配置v2，2026-11-03）

完整核查与论文替换位置见 [严肃核查报告](严肃核查报告_20261103.md)，准确命令见 [当前运行命令](当前运行命令_20261103.md)。

## 1. 部署、对象、密钥与claim

发布者分发前登记，授权核验者持有256位主密钥及外部可信expected claim。只核验登记实例的人脸水印证据集合；不证明物理同框、嵌入前真实、生物身份、整图完整性或保水印编辑必被检出。

64位=uint8人数+uint8逻辑编号+48位HMAC标签；128=8+8+112，人数≤255。标签绑定完整claim、variant、count、index。claim含schema version、image_id、128位nonce、message、config_sha256；编号是逻辑索引，不是空间坐标。实际三个子密钥域watermark/positions/metadata；没有加密或dither。

实验run的nonce由seed/source/key_index确定便于复现，不是安全随机发布；单图new_claim使用随机nonce。实验key随机生成，复现同run要私下保存key，不可公开后仍当保密密钥作安全论证。

## 2. 嵌入与质量

主配置block=stride=12、Δ18、min_roi64、min_blocks3，块std≥2且像素在[5,250]；重叠登记ROI明确排除。QIM遵循论文Q_a={2Δk+aΔ}，每个run固定登记b/s，不实现每ROI自动适配。

Config.version=2拒绝旧码本k*step±step/4的v1配置；metadata envelope和claim的version=1指各自schema版本，配置指纹绑定新码本。所有原图重新登记，旧图/校准不可复用。

登记检查最终uint8码字，写入元数据后再次检查全部脸；自检失败整次登记失败，不删除失败脸缩小范围。重新检测仍可能漏脸，因此自检不等于端到端clean接受。

DCT载荷在人脸内；辅助metadata帧按全图栅格前缀写Y-LSB，可能改到背景，不能声称整图只有脸像素变化。质量测最终PNG，分别提供全图Y、ROI并集Y、逐ROI均值；协议位、重复嵌入实例与metadata_frame_bits分开，不把重复位当净容量。

## 3. PNG内元数据与外部声明

帧格式：CPM1魔数32位+大端长度32位+规范JSON完整metadata，包含HMAC。body有version、claim副本、config、shape、faces、excluded_faces；HMAC认证完整body。UTF-8/ASCII转义/排序键/无额外空白，禁止NaN、Infinity、重复字段；校验schema、版本、类型/范围、shape/bbox/index/blocks、配置及外部claim。

写Y-LSB时搜索临近亮度值使OpenCV定点往返回读成功，只替换帧内像素。不存在任意图失真恒≤2或LSB擦除不影响DCT的保证；容量不足/写入失败保留登记失败记录。metadata_strip修改像素，不是单纯删除EXIF。

默认auto/metadata从PNG取；默认不生成.cpm.json，--debug-metadata才生成副本；显式--metadata只作辅助控制，blind忽略图内外metadata。图内帧损坏/非法HMAC时auto转blind，强制metadata模式为不可判定。合法metadata仅提供框提示，仍重检测当前所有脸并解码像素。

metadata包含claim副本，但不能自行决定待验证发布实例。两模式都需外部可信expected claim，可来自.claim.json或可信登记库；缺claim为UNDECIDABLE。PNG不是只拿图片即可公开验证的凭证。

## 4. 候选、评分与阈值

blind先试当前框0/±1/±2px左上相位，再试block∈{12,16,20,24}、stride∈{b,b/2}，固定顺序至多32候选；辅助模式试合法匹配旧框和当前框。每run公共配置指纹包括候选/资格/强度；记录实际candidate_count。

结构16位投票平票无效；tag平票算错。count/index精确判定，阈值只用于B=L−16的tag匹配比例。独立validation按blind/auto管线校准、冻结；test检查source/group/hash及检测权重/provider/voting签名，不可重叠或改协议。无可行阈值停止，不能用test重选。

独立均匀错key位模型下单候选p=2^-BΣ(k=0..τ)C(B,k)，M候选min(1,Mp)仅是参考并集界；候选间不需独立，但单候选假设仍须成立。不是自适应编辑或实际FAR保证，0误接受不等于FAR为0。

## 5. 三态与集合

full接受要求当前每张检测脸都有可用证据、count相同为N、恰好N份、index组成完整唯一{1,…,N}、每脸tag达到阈值；整图取最差脸分数。roi_qim弱baseline故意用any-face，no_count/no_id消融各关闭部分结构约束。

缺claim/无当前检测脸/不合格当前脸或证据不可用输出UNDECIDABLE；可用证据结构/认证失败为REJECTED；全部满足才ACCEPTED。不可判定不能算通过，也不能全部算成功检出攻击。

漏掉登记脸通常人数失配；检测器完全看不到新增脸则可能无法发现该对象。detector_miss_control人为去掉最大检测脸，不代表自然漏检评估。partial_detected_faces范围更小、clean也可能不通过；所有失败/排除/覆盖分母必须保留。

## 6. 重排与攻击边界

协议允许完整证据空间重排，检测同步失败属于可用性问题；不能把重排拒绝当安全优势。reorder_exact完整ROI无插值平移，越界/目的重叠则skipped；reorder包含尺寸重采样。测试里固定框oracle只验证逻辑，不能当部署基准。

跨实例供体通常claim/key失配；同实例整套证据移植、保留充分重复水印的局部边界编辑可能通过。没有逐像素哈希或语义身份绑定，不承诺强真实性。

离线同实例重放允许，没有nonce消费表/过期/硬件签名，不能声称阻止所有重放。共谋需同宿主≥2key版本；截图/平台默认仅数字模拟；自然漏检、真实截图与平台传输未完成。

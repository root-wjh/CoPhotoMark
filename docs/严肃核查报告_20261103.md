## 2. 元数据与 JSON 的准确解释

PNG 内含 CPM1 魔数32位、长度32位、完整规范JSON metadata（含HMAC）。metadata 有版本、claim副本、config、shape、登记脸记录及排除记录。HMAC校验版本与外部期望claim/config，合法元数据只提供对齐提示，仍需检测当前全部脸并解码像素水印。

其他文件：

| 文件 | 是否可删除 | 作用 |
|---|---|---|
| *.png | 否 | 水印图及图内元数据载体 |
| keys/*.json | 不可丢失/不可公开 | 私钥；实验或授权验证需要 |
| *.claim.json | 不可丢失 | 外部可信期望声明，包含发布ID、nonce、message、配置指纹；也可由可信登记系统供应，文件只是离线实现 |
| *.cpm.json | 可选 | 显式debug副本，默认不生成、不作为默认核验输入 |
| configs/*.json | 应保留 | 公共协议配置 |
| calibration.json | 应保留 | 冻结工作点及验证来源、检测协议签名 |
| *.jsonl | 应保留 | 原图、划分、登记、攻击、逐条得分的可复现日志 |
| environment.json / summary.json | 应保留 | 环境与统计报告 |

“图内存储元数据”不等于“任意陌生人只拿图片即可公开验证”。本系统始终需要授权密钥和可信期望声明；无metadata的blind也不是无key/无message。

## 3. 六类核心场景及新增攻击

| 审稿要求 | 当前内部名称 | 实际执行方式与限制 |
|---|---|---|
| 插入已带水印人脸 | insert_marked | 同split跨图供体，扩画布后贴脸；可能改变原脸检测，须看人数日志 |
| 删除 | delete | 把登记ROI填灰；不等同生成式修复或自然物理移除 |
| 复制 | duplicate | 同图第一张脸替换第二张，测试重复编号；copy_marked_face 为跨图整ROI移植 |
| 重排 | reorder_exact / reorder | 前者完整无插值移动，后者含尺寸重采样；完整证据空间顺序在协议上允许改变，不能要求一律拒绝 |
| 漏检 | detector_miss_control | 在真实当前检测结果中人为去掉最大脸；不是自然漏检率评估。自然漏检需WIDER标注匹配或人工GT，当前未完成 |
| 新增未水印脸 | insert_unmarked | 原始供体ROI插入；检测器看不到新增脸时无法保证发现该对象 |
| 替换 | replace | 未水印供体ROI替换登记ROI |
| 水印复制/移植 | copy_marked_face / watermark_transplant | 整ROI复制和像素差残差移植，非学习式换脸 |
| 共谋 | collusion | 同一源图至少2个不同实验密钥版本取均值；demo默认1key会跳过，完整管线3key才生成 |
| 擦除后重嵌 | erase_reembed_wrong_key | ROI高斯模糊后用错误key登记；攻击者得不到正确key |
| 边界 | boundary_tamper | 10%短边宽矩形边缘；有效重复水印仍可能保留，接受并非不可能 |
| 旋转/缩放/拉伸/模糊/JPEG/裁剪/Cropout | 同名 | 参数、插值、边界与顺序记录在 attack_protocol.json |
| 截图/平台重压缩 | screenshot_simulation / platform_simulation | 仅数字模拟；真实设备截图、真实上传下载另做，不能改名字冒充 |

## 4. 本次实际验证结果，禁止当论文主表

39项pytest通过，包含实际编解码、PNG往返、图内元数据、无sidecar默认链路、错key/声明、集合规则、候选签名与泄漏检查、完整不等尺寸ROI重排、真实GPU回退错误检查等。GPU回退检查使用模拟session；云端CUDA推理仍需用户运行环境自检。

本机CPU对 WIDER_train/images/12--Group 按路径排序前20张做工程检查：

- 20张输入，19张检测到至少2张脸；19次多人图登记尝试，6次登记成功、13次无合格ROI等登记失败。
- 成功6张中仅3张为全覆盖多人登记，另3张部分覆盖保留在登记分母，不参加全脸场景表。
- 全覆盖3张每张1key、1repeat，共57个不同trial、114条blind/auto评分。共谋因只有1key明确跳过。
- clean：blind接受1/3，auto接受2/3。1张原本7脸的登记图重检测只有6脸，auto因缺号拒绝；另一张blind因局部ROI解码分数不足拒绝。
- 删除/复制/插入未水印脸/插入带水印脸/跨图脸复制/替换/受控漏检：两模式均没有接受，但clean本来失败的实例不能据此证明攻击检出率高。
- reorder_exact：blind接受0/3、auto接受2/3。协议逻辑顺序无关不代表端到端重检测/重同步已可靠。
- boundary_tamper：blind接受0/3、auto接受2/3，说明部分像素修改保留有效证据可通过，不能宣称强局部篡改检测。
- 插入未水印脸3次，仅2次观察到检测人数增加，另1次人数没增加；仍拒绝可能受ROI漂移影响，不能说新增脸均被检测。

原始逐条日志、场景图保存在工作区审计目录，项目 audit/20261103 仅保留清晰审计记录。旧版本的结果不适用于新QIM码本。

正式report另输出全覆盖多人表和 clean 已接受的配对条件表，同时保留总表与登记分母。条件表不能替代总表，否则会掩盖低可用率。

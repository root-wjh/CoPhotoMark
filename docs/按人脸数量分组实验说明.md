# 登记人脸数与可用率实验

## 已完成

新增 cophotomark/face_count_availability.py，独立读取现有 test/scores.jsonl，不重新核验、不改变阈值。运行根目录“运行人脸数量分组实验.ps1”即可复现统计；输出目录自动带时间，拒绝覆盖已有报告。

默认使用 runs/wider_threshold_20261110/test/scores.jsonl，选取 genuine 且 split=test 的 clean 和 jpeg95。各模式、各攻击独立统计，主表按 N=2、3、>=4 分组，CSV还包含每个确切N及混合条件汇总。混合条件不替代单攻击主表。不要将旧protocol结果称为当前算法重新运行结果；summary.json记录输入和脚本哈希、原始配置签名和阈值。现存历史阈值不会被本脚本修改，若论文改用新协议和阈值，应传入相应新test/scores.jsonl重新汇总。

接受率是先计算每张源图在该条件下所有密钥/重复的接受比例，再对源图等权平均；独立图像数与试验数分别报告。不把重复密钥、重复攻击或两个模式当成更多图像。拒绝、不可判定与运行异常全部保留为未接受，错误另计。CSV的95%区间按源图bootstrap；单源图不计算区间。耗时为有效试验的total_ms（核验内部耗时），非end_to_end_ms，另列有效计时试验数。auto是元数据辅助并可盲回退的部署流程，不能称为纯元数据模式；实际路由计数见CSV。

现有测试集32张独立图，N分布：2人7张，3人5张，4人8张，5人4张，6人7张，7人1张。不存在1人组，因此主表不虚构1人数据。2/3/>=4合并在生成结果之前固定，保留确切N结果便于审核。样本量和图像条件不同，分组比较为描述性结果，不构成人数的因果效应。不要声称接受率必然单调下降。

## 文件

- availability_by_face_count.csv：各组样本量、接受/拒绝/不可判定/错误、接受率、置信区间和耗时。
- table_face_count.tex：紧凑论文表格，包含clean和JPEG Q95两条件、auto和blind两模式。
- acceptance_by_face_count.png/pdf：确切N的接受率曲线。
- summary.json：数据来源、原始配置/阈值、输入哈希及统计方法。
